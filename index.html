How it works

Trust you can verify, not guess

Only evidence your server can check grants a token. Browser signals can raise suspicion, but they can never grant access.

01

Argon2id proof-of-work

A small, memory-hard computation runs in the visitor's browser and is bound to the request. It costs a person a moment and costs a bot farm real money at scale.

• Works with keyboard and screen readers
• Tunable difficulty
02

WebAuthn step-up

Returning visitors can use a passkey credential your server registered. Signature counters are checked, and credentials expire and can be revoked.

• Counter-checked assertions
• Anonymous registration with PoW
03

Privacy-preserving tokens

Tokens are issued through an RFC 9497 VOPRF (ristretto255-SHA512), single-use, and replay-protected, with no cookies and no cross-site identifiers.

• Verified against the official RFC vectors
• Shared nullifier store

Developer experience

Up and running in minutes

server.ts@biokyn/server
import { BioKynVerifier, biokynExpress, generateServerSecrets,
  createRateLimiter, MemoryRateLimitStore } from '@biokyn/server';

const verifier = new BioKynVerifier({
  issuer: 'verify.example.com',
  ...generateServerSecrets(),
  sites: [{ origin: 'https://example.com',
            secret: process.env.BIOKYN_SITE_SECRET! }],
});

app.use(express.json());
app.use(biokynExpress(verifier, {
  basePath: '/biokyn',
  rateLimit: createRateLimiter({ store: new MemoryRateLimitStore() }),
}));
browser.ts@biokyn/client
import { requestInclusiveToken } from '@biokyn/client';

const { token } = await requestInclusiveToken({
  basePath: '/biokyn',
  expectedPublicKey, // pin your issuer key
});

// Send `token` to your backend, which calls
// POST /siteverify with { secret, response: token }
